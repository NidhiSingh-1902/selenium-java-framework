Test Automation Framework

selenium-java-framework

A Page Object Model framework built on Selenium 4, Java 17, and TestNG for end-to-end testing of SauceDemo. Clone, extend, and run — no additional setup required.

54 tests passing 8 modules Selenium 4.18.1 Java 17 TestNG 7.9.0

Prerequisites

Install these tools before cloning. Versions must match to avoid ChromeDriver compatibility errors.

Java JDK
17 or higher
Set JAVA_HOME in system environment variables
Apache Maven
3.9.x
Add Maven bin/ to your PATH
Google Chrome
150.x (must match driver)
Check your version: chrome://settings/help
ChromeDriver
150.x (auto-managed)
WebDriverManager downloads it automatically — no manual install

Quick Start

1
Clone the repository
$ git clone https://github.com/NidhiSingh-1902/selenium-java-framework.git
$ cd selenium-java-framework
2
Run the full suite

This compiles the project, launches Chrome, runs all 54 tests, and generates a report.

$ mvn test

# Run a single module only
$ mvn test -Dtest=CartTest

# Run multiple modules
$ mvn test -Dtest=CartTest,CheckoutStep1Test
3
Check results

Test reports are written to target/surefire-reports/ after each run. Open any .txt file for a plain-text summary or the .xml files for CI integration.

Add a New Page Object

Every page of the application gets its own class. The pattern is always the same: extend BasePage, declare locators with @FindBy, write action methods.

Rule: Never put raw Selenium calls in test classes. All browser interactions belong in page objects.
package com.pages;

import com.framework.pages.BasePage;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.support.FindBy;

public class MyNewPage extends BasePage {

    // 1. Declare locators with @FindBy — PageFactory wires them up automatically
    @FindBy(id = "page-title")
    private WebElement pageTitle;

    @FindBy(css = ".submit-btn")
    private WebElement submitButton;

    // 2. Constructor — always call super(driver)
    public MyNewPage(WebDriver driver) {
        super(driver);
    }

    // 3. Page state
    public boolean isPageLoaded() {
        return isDisplayed(pageTitle)
            && driver.getCurrentUrl().contains("my-page");
    }

    // 4. Action methods — use inherited helpers, not raw Selenium
    public void clickSubmit() {
        wait.waitForVisible(submitButton);
        jsClick(submitButton);
        wait.waitForUrlContains("next-page");
    }
}

Register it in testng.xml

Add a new <test> block for the corresponding test class:

<!-- src/test/resources/testng.xml -->
<test name="My New Page Tests">
    <classes>
        <class name="com.tests.MyNewPageTest"/>
    </classes>
</test>

Add a New Test Class

Test classes extend BaseTest (which manages the browser lifecycle) and follow the Arrange → Act → Assert pattern.

package com.tests;

import com.framework.base.BaseTest;
import com.pages.LoginPage;
import com.pages.MyNewPage;
import org.testng.Assert;
import org.testng.annotations.Test;

public class MyNewPageTest extends BaseTest {

    // Helper — shared setup steps go here, not in @BeforeMethod
    private MyNewPage loginAndNavigate() {
        LoginPage login = new LoginPage(getDriver());
        login.login("standard_user", "secret_sauce");
        // ... navigate to the page
        return new MyNewPage(getDriver());
    }

    // Test ID format: TC-[MODULE]-[NUMBER]
    @Test(priority = 1, description = "TC-MN-01: Page should load with correct heading")
    public void pageLoadsTest() {
        // Arrange + Act
        MyNewPage page = loginAndNavigate();

        // Assert
        Assert.assertTrue(page.isPageLoaded(), "Page should be loaded");
        log.info("TC-MN-01 PASSED");
    }
}

BasePage Methods

All page objects inherit these methods. Use them instead of calling Selenium directly.

MethodWhen to use
click(element) Standard click — waits for element to be clickable first
jsClick(element) Use this for all React buttons and links. JavaScript click bypasses React's synthetic event system issues
type(element, text) Clear field and type — for non-React inputs (login form, search boxes)
typeReact(element, text) Use this for React controlled inputs. Sets value via native setter + fires an input event so React's onChange updates internal state
getText(element) Get visible text — waits for element visibility, returns trimmed string
isDisplayed(element) Safe visibility check — returns false instead of throwing when element is absent
scrollToElement(element) Scroll element into viewport — use before interacting with off-screen elements
getPageTitle() Returns the browser tab title
getCurrentUrl() Returns the current browser URL

WaitUtils (via wait.*)

MethodWhen to use
wait.waitForVisible(element)Wait until element is visible — use before reading text or clicking
wait.waitForClickable(element)Wait until element is enabled and clickable
wait.waitForUrlContains(fragment)Wait for navigation — pass a URL fragment like "cart.html"
wait.waitForTextInElement(By, text)Stale-safe text wait — use after React re-renders a button (e.g. "Add to cart" → "Remove")

React-Specific Patterns

SauceDemo is built with React. Two common Selenium approaches silently fail on React pages — here is why and what to use instead.

Clicking buttons and links

Problem: element.click() triggers a synthetic click that React may not handle. Use jsClick(element) for all cart buttons, nav links, and form submits.
// ✗ Do not use — misses React event handlers on re-rendered nodes
element.click();

// ✓ Use this — fires a native DOM click React always catches
jsClick(element);

Typing into form fields

Problem: element.clear() resets the DOM value but does not update React's internal state. The form still sees an empty field when submitted. Use typeReact() for all checkout form inputs.
// ✗ Do not use for React inputs — React's internal state stays empty
element.clear();
element.sendKeys("John");

// ✓ Use this — sets value via native setter + dispatches 'input' event
typeReact(firstNameField, "John");   // React sees the value correctly
typeReact(lastNameField,  "Doe");
typeReact(postalCodeField, "12345");

Waiting after React state changes

Problem: After clicking "Add to cart", React re-renders the button node. A stale WebElement reference to the old node throws StaleElementReferenceException. Use waitForTextInElement(By, text) with a locator, not an element reference.
// ✗ Stale — the By.id locator-based element reference may be dead after React re-render
wait.until(ExpectedConditions.textToBePresentInElement(button, "Remove"));

// ✓ Safe — re-finds the element by locator on each retry
By locator = By.cssSelector(".inventory_item:nth-child(1) .btn_inventory");
wait.waitForTextInElement(locator, "Remove");

Running Tests

mvn testFull suite — all 54 tests via testng.xml
mvn test -Dtest=CartTestSingle test class

Test reports

After mvn test, reports appear in target/surefire-reports/. Each class gets its own .txt summary. Look for lines marked FAILURE! to identify broken tests.

# Open the summary for a specific class
$ cat target/surefire-reports/com.tests.CartTest.txt
